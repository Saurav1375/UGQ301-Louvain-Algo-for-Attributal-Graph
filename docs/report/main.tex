\begin{abstract}
This report documents the complete implementation, benchmarking, and analysis of our extensions to LouvainNE for attributed graphs. The objective from our Statement of Purpose (SOP) was to integrate attributes \emph{inside} the LouvainNE pipeline while retaining strong efficiency. We implemented two concrete attributed strategies: (i) an internal attributed LouvainNE pipeline with attributed hierarchy construction (\texttt{recpart\_attr}) and attributed embedding generation (\texttt{hi2vec\_attr}), and (ii) SOP Method 1, a structural reweighting pipeline that injects attributes into edge weights before hierarchy construction (\texttt{recpart\_weighted}). We also implemented complete benchmark scripts, link-prediction evaluation, hyperparameter sweeps over attribute weights, CSV export pipelines, and reproducible figure generation. Experiments were run on the real datasets Cora and BlogCatalog and compared against LouvainNE, DeepWalk, and Node2Vec. The final results show that Method 1 preserve gives the best speed/accuracy tradeoff on Cora, while Method 1 augment gives the strongest overall quality on BlogCatalog.
\end{abstract}

\textbf{Course:} UGQ301.

\textbf{Core problem:} LouvainNE is scalable and effective for structural graphs, but it does not use node attributes. In real networks, structure and semantics both matter (for example, two papers can be semantically similar but not directly linked).

\textbf{Mandatory constraints that guided the implementation:}
\begin{itemize}
  \item Attributes must affect LouvainNE internals (not only post-processing).
  \item Runtime should remain near LouvainNE-style efficiency (avoid GNN-style message passing and backprop over full adjacency).
  \item Comparisons should include structural and popular random-walk baselines.
\end{itemize}

\section{Beginner-Friendly Background}
\subsection{What is graph embedding?}
A graph embedding maps each node to a fixed-length vector. Similar nodes should have vectors that are close in space. These vectors are then used for tasks like node classification and link prediction.

\subsection{Why LouvainNE is fast}
LouvainNE first builds a \emph{hierarchy} of communities using Louvain partitioning, then converts hierarchy paths to vectors. This avoids expensive epoch-based training over all edges.

\subsection{What ``attributed graph'' means}
Each node has additional features (attributes), such as text/topic features (Cora) or group-membership indicators (BlogCatalog).

\subsection{Where attributes are integrated (internally)}
\textbf{Stage 0: graph construction for SOP Method 1.}
Before Louvain partitioning, we construct a weighted graph in which attributes directly influence edge strengths. Two variants were implemented.

\textbf{Edge-preserving Method 1:}
\[
w(i,j) = \alpha \cdot 1 + (1-\alpha)\cdot \mathrm{sim}(x_i, x_j)
\]
for existing graph edges $(i,j)$.

\textbf{Edge-augmenting Method 1:}
\[
w(i,j) = (1-\alpha)\cdot \mathrm{sim}(x_i, x_j)
\]
for top-$k$ semantic neighbors added from attribute space. In our implementation, $\mathrm{sim}$ is cosine similarity normalized into $[0,1]$. This keeps the LouvainNE pipeline intact while changing the graph that Louvain sees.

\textbf{Stage 1: hierarchy construction.}
During Louvain node moves, we changed gain from purely structural to:
\[
\Delta = \Delta Q_{\text{struct}} + \lambda\, s(x_u, C)
\]
where $x_u$ is node attribute vector, $C$ is target community, and $\lambda$ controls structure-vs-attribute influence.

\textbf{Stage 2: embedding generation.}
In hierarchy-to-vector conversion, we inject an attribute-projection term:
\[
z_u = z^{\text{hier}}_u + \beta\,P x_u
\]
where $P$ is a random projection and $\beta$ controls attribute strength.

This satisfies the requirement that attributes influence partitioning, graph formulation, and final vectors.

\subsection{Why Method 1 matters}
Method 1 is important because it is closer to the speed-preserving spirit of LouvainNE than many neural attributed methods. It avoids message passing, backpropagation through edges, and epoch-wise graph training. The preserve variant is especially efficient because it only changes existing edge weights and then reuses the standard LouvainNE hierarchy-plus-hi2vec pipeline.

\section{Data and Preprocessing}
\subsection{Datasets used (real only)}
\begin{itemize}
  \item \textbf{Cora:} citation network, text-like sparse features.
  \item \textbf{BlogCatalog:} social network, group-membership attributes.
\end{itemize}

\subsection{Generated files per dataset}
\begin{itemize}
  \item \texttt{edgelist.txt}: undirected graph edges.
  \item \texttt{attributes.txt}: node features per line.
  \item \texttt{labels.txt}: node class labels for node classification.
\end{itemize}

\subsection{Link prediction protocol}
We create:
\begin{itemize}
  \item \texttt{lp\_train.edgelist} for embedding training,
  \item \texttt{lp\_test\_pos.txt} for true held-out edges,
  \item \texttt{lp\_test\_neg.txt} for sampled non-edges.
\end{itemize}

Then score node pairs with embedding similarity and report AUC/AP.

\section{Evaluation Metrics (Explained Simply)}
\begin{itemize}
  \item \textbf{Node accuracy:} how often predicted node class equals true class.
  \item \textbf{Link AUC:} probability that a real edge gets higher score than a fake edge.
  \item \textbf{Link AP:} ranking quality emphasizing positive edges.
  \item \textbf{Total time:} end-to-end runtime for each method.
  \item \textbf{Embedding time:} only graph-to-vector generation time.
\end{itemize}

\textbf{Interpretation for beginners:}
\begin{itemize}
  \item On \textbf{Cora}, Method1-Preserve is the most practical result: it beats LouvainNE on node classification while staying close in total runtime.
  \item On \textbf{BlogCatalog}, Method1-Augment gives the strongest quality among all tested methods, but it is slower because semantic edge construction costs extra time.
  \item Attr-LouvainNE improves BlogCatalog over structural LouvainNE, but on Cora it remains weaker than both structural LouvainNE and Method 1.
  \item LouvainNE-style methods still remain much faster than DeepWalk and Node2Vec in the actual embedding-generation step.
\end{itemize}

\subsection{Method 1-specific observations}
\begin{itemize}
  \item \textbf{Preserve mode} is the speed-oriented version. It does not change graph size, only edge weights, so it stays close to the original LouvainNE runtime.
  \item \textbf{Augment mode} adds semantic edges from attribute space, which can improve quality but also adds a significant preprocessing cost, especially on sparse high-dimensional datasets such as Cora.
  \item The benchmark CSV separates this cost into \texttt{weight\_build\_time\_sec}, which makes the tradeoff visible and fair.
\end{itemize}

python3 scripts/sweep_attr_params.py \

  --edgelist data/real/cora/edgelist.txt \
  --attributes data/real/cora/attributes.txt \

\section{Limitations and Future Work}
\begin{itemize}
  \item Performance is dataset-dependent: Method 1 preserve is best balanced on Cora, while Method 1 augment is strongest on BlogCatalog.
  \item More tuning dimensions are possible (projection strategy, similarity design, label split policy).
  \item Method 1 augment can become expensive when attribute-space candidate generation is large.
  \item Additional baselines and standardized public splits can strengthen external comparability.
\end{itemize}

\section*{Conclusion}
This work delivers a complete, reproducible attributed extension of LouvainNE with integrated benchmarks, sweeps, plots, and reporting tooling. The final system now includes both an internally attributed LouvainNE variant and SOP Method 1 structural reweighting. The preserve version of Method 1 demonstrates that attribute-aware graph reformulation can improve accuracy while staying close to LouvainNE-level efficiency, while the augment version shows that higher-quality attributed neighborhoods can improve downstream quality further when additional preprocessing cost is acceptable.
